### Fortinet FortiMail zero-day (CVE-2026-104286) exploited, fixes not yet shipped
- **Source:** BleepingComputer — https://www.bleepingcomputer.com/news/security/fortinet-warns-of-critical-fortimail-flaw-exploited-in-zero-day-attacks/ (advisory FG-IR-26-175: https://fortiguard.fortinet.com/psirt/FG-IR-26-175, not read directly)
- **Tag:** security
- **What happened:** Fortinet disclosed on Oct 1 that an unauthenticated path-traversal flaw (CVSS 9.8) in FortiMail's web interface is being exploited as a zero-day, and CISA added it to KEV the same day (due Oct 4, forensic triage required under BOD 26-04).
- **Why it matters:** Mail gateways sit in the trust path for phishing defence and often hold cleartext mail and credentials; if you run FortiMail with a reachable management interface, the only available control right now is Fortinet's workaround (restrict/disable internet access to the management and IBE components). [UNVERIFIED: sources disagree on whether fixed builds 8.0.2 / 7.6.7 / 7.4.9 are released or "upcoming," and on the exact affected ranges — check the Fortinet advisory.]
- **Angle:** Fortinet edge/appliance zero-days keep recurring — what does a "workaround only" window look like in a change-controlled regulated environment?

### Cisco Catalyst SD-WAN Manager auth bypass (CVE-2026-76504) exploited, no workaround
- **Source:** Help Net Security — https://www.helpnetsecurity.com/2026/10/01/new-cisco-sd-wan-zero-day-exploited-in-the-wild-cve-2026-76504/ (KEV entry on cisa.gov: added 2026-09-30, due 2026-10-03, forensic triage required)
- **Tag:** security
- **What happened:** Cisco confirmed zero-day exploitation of an API authentication bypass in SD-WAN Manager (CVSS 9.8 per The Hacker News) that gives an unauthenticated remote attacker admin-level access; Help Net counts this as the fifth exploited Cisco SD-WAN zero-day this year.
- **Why it matters:** SD-WAN Manager controls the WAN fabric that links branches, data centres and cloud VPCs, so admin takeover is a network-wide problem; Cisco says there is no workaround, and releases earlier than 20.9.10.1 must migrate to a fixed version rather than patch in place.
- **Angle:** What compromise assessment would you run on a controller that was internet-reachable before the patch?

### Bitget's $387.5M theft traced to zero-days in third-party security appliances
- **Source:** BleepingComputer — https://www.bleepingcomputer.com/news/security/bitget-hacked-via-zero-day-in-third-party-security-products/
- **Tag:** security
- **What happened:** Investigations by SlowMist and Mandiant found the attackers got into two third-party security appliances (vendors not named), planted a web shell, moved to the production wallet job server, and used a custom withdrawal tool; earliest malicious activity in logs is Aug 31, with the theft around Sept 25.
- **Why it matters:** The foothold sat inside security tooling for roughly four weeks before money moved, and the fraudulent transfers passed the exchange's own validity checks — a direct lesson on trusting appliances with privileged network paths, on log retention long enough to cover a month-long dwell, and on the third-party-risk scoping that DORA/PCI-style programs require.
- **Angle:** If a security appliance is compromised, what does your segmentation say it can reach?
- [UNVERIFIED] North Korea attribution is Bitget's CEO's claim based on IP patterns and on-chain analysis, reported secondhand; I did not read the SlowMist/Mandiant reports directly.

### AI agent chained two Zammad zero-days to root a Dutch security non-profit
- **Source:** Help Net Security — https://www.helpnetsecurity.com/2026/10/01/divd-agentic-ai-attack-breach/ ; SecurityWeek — https://www.securityweek.com/zammad-zero-days-exploited-in-ai-powered-divd-hack/
- **Tag:** security
- **What happened:** DIVD says an agentic-AI-driven intrusion on Sept 21 used CVE-2026-102489 (session hijack to RCE) and CVE-2026-102490 (local privilege escalation to root) in the Zammad helpdesk; it published details on Sept 30 and says segmentation and incident response stopped it going deeper.
- **Why it matters:** It is a concrete, named case of an autonomous agent going from initial access to root in seconds, which compresses detection-and-response time assumptions; self-hosted ticketing systems also tend to hold customer data and credentials in tickets.
- **Angle:** Which of our self-hosted internal tools would we not know to patch on a weekend?
- [UNVERIFIED] Patch status conflicts: one report says Zammad released version 7 as the fix; another says the root escalation has no patch for any version as of Oct 1. Check the Zammad advisory before advising anyone. DIVD has not published the agent's logs or named a model.

### Truffle Security: 543,699 still-valid credentials found in public GitHub repos
- **Source:** Cyber Security News — https://cybersecuritynews.com/543699-unique-credentials-exposed/ ; summary at daily.dev — https://daily.dev/posts/over-543-000-valid-credentials-exposed-in-public-github-repositories-fblhmhuem (BleepingComputer also covered it; primary Truffle Security report not read)
- **Tag:** both
- **What happened:** A scan of 224M public repos found 543,699 unique credentials that still authenticated when tested July 27–28, with a median exposure of 784 days; of 126,963 exposed Google Cloud service-account credentials, 69,041 were still valid.
- **Why it matters:** Push protection cut leaks by about 53% in the secret types it covers, but over half of live secrets are types it doesn't block (e.g. database connection strings, Google API keys), and deleting a file does not revoke a key — rotation is the only fix, which is the cloud-IAM hygiene gap behind many breaches.
- **Angle:** Do we have a revoke-on-detect path for cloud keys, or only alerting?
- [UNVERIFIED] Figures come from secondary coverage of the Truffle report.

### Microsoft Entra ID will enforce a CSP that blocks injected scripts on sign-in pages
- **Source:** BleepingComputer — https://www.bleepingcomputer.com/news/security/microsoft-to-block-entra-id-script-injection-attacks-starting-october/ ; Message Center MC1481309 mirror — https://mc.merill.net/message/MC1481309
- **Tag:** both
- **What happened:** Starting mid-October 2026 and completing by late October, login.microsoftonline.com will only run scripts from trusted Microsoft sources; browser extensions or tools that inject code into the sign-in page may stop working, but sign-in itself keeps working. Entra External ID tenants are not affected and no tenant configuration is needed.
- **Why it matters:** It hardens the credential-entry page against XSS and injection, but any internal tooling that relies on injecting into the login page will quietly break in the next two to three weeks, so test now (browser console shows CSP violations).
- **Angle:** What in our environment touches the Entra sign-in page that we haven't inventoried?

### Google Threat Intelligence: AI-found bugs are being exploited within days
- **Source:** Help Net Security — https://www.helpnetsecurity.com/2026/10/01/google-ai-discovered-vulnerabilities-remote-code-execution/
- **Tag:** security
- **What happened:** GTIG's analysis of Jan 2025–Aug 2026 data says one threat cluster exploited an AI-agent-discovered BeyondTrust flaw (CVE-2026-1731) within four days of public disclosure and five more clusters within seven days; exploited AI-tooling flaws so far include LiteLLM (CVE-2026-42271) and two Langflow bugs.
- **Why it matters:** The window between disclosure and exploitation is shrinking toward days, which matters for any patch SLA measured in weeks, and AI-serving components (proxies, workflow builders) are now showing up in exploited-vulnerability data.
- **Angle:** Is our emergency-patch path realistically under a week for internet-facing admin tooling?
- [UNVERIFIED] Summarised via Help Net Security; the GTIG report itself was not read.
